# Teacher Materials

**This is the shared company case for every student. Treat these files as read-only during the assignment.**

The application discovers `.md`, `.txt`, `.json`, and `.csv` files in this folder automatically. Students do not need code changes when the dataset changes.

## Dataset status

The employee file was supplied by the course teacher. The other files are a **clearly labelled demo case** generated for development and teaching. The case is fictional; the data must not be used for real employment, financial, or operational decisions.

## Replacing the dataset

1. Close the Streamlit app and any session you do not want to mix with the new dataset.
2. Replace the contents of this folder with the new company files. Keep the folder name `teacher_materials`.
3. Supported table format: UTF-8 CSV. Supported document formats: UTF-8 Markdown, plain text, or JSON.
4. Keep the first Markdown heading in `company_profile.md` as the company name (for example `# Meridian Consumer Group, Inc.`). If no profile is found, the app uses a neutral fallback.
5. Refresh the integrity manifest from the project root:

   ```powershell
   py tools/lab.py teacher-manifest --write
   ```

6. Run the environment check:

   ```powershell
   py tools/lab.py doctor
   ```

7. Start the app:

   ```powershell
   py -m streamlit run app.py
   ```

   On Windows, `run.bat` does the same thing after `setup.bat` has installed the dependencies.

The app does not require an API key. The AI Manager is the student's own AI harness; the lab environment does not call an AI model.

## Replacing only some files

The app discovers whatever is present. If a CSV is malformed or missing, the app and `doctor` will report it. If you add a new file, it appears automatically. If you remove a file that is cited in an existing session, the PDF still contains the citation but the session log will show a historical reference.

## Demo data generation

The demo CSVs can be regenerated from the supplied employee file:

```powershell
py scripts/generate_demo_data.py --force
```

This overwrites the generated demo CSVs and refreshes `employees.csv` from the source employee file. It does not modify the original source file. Review the generator before using it with a different employee dataset.

## Integrity manifest

`.dataset_manifest.json` records a SHA-256 hash for each discoverable teacher file. The app shows whether the current files match the manifest. The manifest is a warning system, not a lock: a student with file-system access could still edit the files. For assessment, distribute a fresh copy of this folder to students and keep a teacher master copy.

## File-design guidance

- Keep company documents concise and factual.
- Give every CSV a header row and stable column names.
- Use ISO dates (`YYYY-MM-DD`) and `YYYY-MM` months.
- State the currency and units in the document or column name.
- Avoid employee names or other personal data.
- Do not add files that contain answer keys or marking notes; students can read every discoverable file.
- If you include a data dictionary, keep it in this folder; it is useful company context.

## Submission expectation

Students submit exactly two files:

1. The PDF session report generated by the app.
2. A ZIP containing their active Markdown instruction files.

They do not submit the teacher dataset, the SQLite database, or application code.
